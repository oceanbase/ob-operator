OceanBase 湖库：单节点体验包
============================

用户只需要「解压 → 执行一个安装命令 → 打开 Dashboard」。Dashboard、Prometheus、
Alertmanager 默认随湖库安装在同一个 Helm release 中，不需要单独运行安装脚本。

1. 准备
-------
在目标 Kubernetes Worker 上执行。需要 Linux amd64、Kubernetes >=1.27、Helm >=3.12、
kubectl、jq、可用的默认 StorageClass，以及管理员 kubeconfig。推荐独立 8 核、32GiB
以上内存的体验机；脚本根据已占用资源计算能否安装，磁盘还需容纳镜像和PVC。
本包不安装操作系统或 Kubernetes，不会修改已有共享 Operator。

交付只有一个 tar：湖库、Dashboard、诊断、MinIO/mc 镜像和校验清单都在包内。
把这一个 tar 复制到目标机器即可，不需要旁边的缓存包或校验文件，不需要手工导入镜像。

  tar -xf oceanbase-lakehouse-具体版本.tar
  cd oceanbase-lakehouse-具体版本
  ./install.sh

安装入口先自动核对包内 SHA256SUMS，文件缺失或损坏时在执行安装器前停止。
请保留包内原文件；自定义配置另存为 my-values.yaml，通过 -f 传入。
然后检查版本、存储、节点状态、剩余资源、Operator/Webhook 和镜像 ID；
只导入缺少或不匹配的镜像。在没有 Operator 的单节点集群上，安装配套 cert-manager
与支持湖库的 Operator。已有但不完整/不兼容的组件会给出明确错误，要求先修复。
随后依次安装存储、LogService、Observer，等待 Dashboard 三个容器就绪，并验证
节点内 HTTP。诊断镜像默认随主包导入，并检查 Observer 中可调用的 Python 3
及 tarfile/gzip 模块（支持发行版自带的 platform-python）；无需在 Observer 中安装 tar。
日志收集时才按需启动诊断 Job。整个过程输出阶段、等待时间及失败诊断，失败不自动删除数据库。

交互终端默认原地刷新阶段状态，不重复刷满等待日志。等待数据库资源就绪时，会显示
资源状态、Pod 就绪/调度数量及可识别的阻塞原因；Pod 信息可能使用短期缓存，会标明
快照时间。耗时刷新不代表 Kubernetes 查询成功，查询失败时明确标为不可用。
安装成功后停止刷新，再打印完整的 Dashboard 访问说明。失败时保留错误摘要和
私有详细日志位置，安装日志及状态提示使用英文。

将输出重定向到文件、在 CI 中执行或使用 TERM=dumb 时，自动使用逐行日志，不输出
终端控制字符。终端空间不足时也会退回逐行输出。可显式选择逐行输出，便于复制或留档：
  ./install.sh --progress plain

默认 --progress auto 根据终端能力选择显示方式，不改变安装步骤、超时或数据保留策略。

默认 release=ob-demo、namespace=ob-helm-demo；LogService 3×1CPU/4GiB，Observer
2CPU/10GiB，MinIO及Dashboard另外占用资源。首次随机生成并保存两个数据库集群ID。
本入口为单 Worker 体验，不提供跨节点HA承诺；高级多节点使用 charts/ 下原流程。

2. 打开 Dashboard
-----------------
安装成功直接打印 Dashboard 访问说明、用户名 admin、初始密码文件位置（0600）。
NodePort 模式下，默认 ./install.sh 自动选择对外地址，优先级为：本次显式指定的
--dashboard-host、已保存的显式地址、Kubernetes Node ExternalIP、节点直接配置的
公网 IP、阿里云 ECS 元数据中的公网 IP/EIP。元数据仅在确认安装器运行于目标
Worker 时读取；不会使用第三方公网 IP 查询服务，也不会把管理机的公网 IP 当成
目标 Worker 的地址。
在浏览器可达的网络内打开 Dashboard 地址，读取密码文件，首次登录按页面提示修改密码。
密码不打印在安装日志中；已修改密码的账号继续使用当前密码，不会被升级重置。
数据库会出现在 Dashboard 中，无需额外安装或注册。

如果无法发现对外地址，摘要会显示 unavailable，并将私网地址明确标为内部地址；
不会把私网地址当作已可从外网访问的 Dashboard 链接。可指定公网 IP、域名，或
浏览器所在网络可达的节点地址：
  ./install.sh --dashboard-host 服务器公网IP

访问摘要成功生成后，显式指定的地址按 Kubernetes 集群、namespace、release
隔离保存，后续续跑和 --show-access 会自动复用；再次指定 --dashboard-host
可更新地址。自动发现的 IP 不保存，下次会重新发现，避免服务器公网 IP 变化后
仍展示过期地址。

默认新装使用 Kubernetes 自动分配的 NodePort。网络安全组/防火墙需要允许浏览器
访问该端口；自动发现地址不代表外网防火墙已经放行。安装器继续通过节点内部地址
探活，成功摘要只显示该检查的通过状态，不会再把探活 URL 与浏览器访问 URL 并列。
不会自动修改云安全组。已有 release 的 Service 类型和自定义 values 保留；若需要
改为直接节点访问，可在同一安装命令中显式添加 --access nodeport。也支持
--access clusterip，其地址仅在集群网络内可达，不会因 --dashboard-host 变成外网服务。

重新查看访问说明（不会重建数据库）：
  ./install.sh --show-access

更新访问地址（不会重建数据库）：
  ./install.sh --show-access --dashboard-host 新的公网IP或域名

3. 预检查、续跑、自定义
-----------------------
只读检查（无镜像导入、无 Kubernetes 修改、无密码文件导出）：
  ./install.sh --check

湖库安装阶段失败后，处理提示原因，再执行同一条命令。如果首次安装配套
Operator/cert-manager 中断并留下不完整组件，需要先修复该前置组件，安装器不会
自动覆盖或删除它。已存在的 Helm release 配置自动保留，
首次安装中断前保存的配置也会复用。已有集群ID、资源规格、存储、账号不恢复为
新建示例。显式传入的新 values 覆盖保留配置；不要随意修改存储身份或集群ID。

  ./install.sh --release my-ob --namespace my-ob -f my-values.yaml

选择节点：--node 节点名。入口必须在该 Worker 上执行，避免把镜像导入错误主机。
K3s/containerd、Docker 自动识别；非 K3s 的 containerd 需明确 --containerd-address
和 --cri-endpoint，两个参数指向同一本机 Unix socket，不推测运行时。

受保护的续跑 values、ACCESS.txt 和初始密码保存在包内 .lakehouse-install/ 下。
不同 Kubernetes 集群、namespace、release 分开保存；不要把此目录提交到 Git
或共享给无关人员。Helm 的详细日志位于安装输出显示的私有临时目录。

4. 范围和数据保留
-----------------
这是一套 Linux amd64 内部 QA 体验包。本版更新日志下载后端、helper 和诊断镜像，
保留原 Observer 镜像。诊断工具通过容器已有的 Python 完成日志打包和传输。
真实源码版本和镜像 ID 见 image-lock.json。
MinIO/mc 是独立第三方 AGPL-3.0 软件，其镜像包含在本 tar 的 images/ 目录中，
不改变其许可证。charts/ 中的 Helm Chart 本身不包含容器镜像。

功能范围：本包覆盖湖库运行、Dashboard 基础管理、监控与日志下载。obdiag 和
oceanbase-helper 使用固定版本/镜像ID，归档在主包内，无需用户手工拉取。日志
收集会检查采集结果后发布附件；失败摘要不能被当成成功日志包。巡检/告警诊断
也使用这些镜像，但各自场景需要独立验证，不因镜像已就绪而宣称全部通过。
SQL分析器镜像仍需另行准备。

从旧QA包升级诊断功能：保留相同release/namespace，显式使用包内镜像升级配置：
  ./install.sh -f values/diagnostics-upgrade.yaml --dashboard-host 服务器公网IP
该文件仅更新Dashboard和诊断镜像，不修改Observer镜像、集群ID、规格、存储或账号。
诊断升级不要求重启Observer。Dashboard更新期间页面可能短暂不可用；安装入口仍会
检查现有Observer是否具备日志采集所需能力，缺少时明确报错。

不要通过删 namespace、PVC、CR 或 helm --force/--atomic 处理安装失败。卸载默认
保留数据库CR、凭据和存储，并不回收磁盘，也不代替备份。已有镜像/身份不兼容时
应明确迁移，不会在后台重建数据库。更多配置见 charts/oceanbase-lakehouse/USAGE.txt。
